# 07 · 测试、调试与性能

## 1. 测试目标

测试不是只验证“页面能打开”，而是保护以下合同：

- 角色手感参数稳定；
- 房间数据合法且可推进；
- 已删除的技能不会重新出现；
- Boss 阶段不能跳过；
- 传送门保持关闭；
- 摄影机不晃；
- 高清画布不会退回低清；
- 手机触控不会卡键、丢失第二根手指或在关闭后残留界面；
- 残影不会堵住复活体积，右键只删除点中的一具；
- 动作锁后的检查点可以从平台顶部直接触发；
- 发布单文件能在浏览器独立启动。

## 3. 运行测试

```bash
cd source
npm ci
npm test
```

生产构建同时执行 TypeScript 检查：

```bash
npm run build
```

构建顺序为 `tsc --noEmit` → `vite build` → 单文件内嵌。

## 4. 房间静态校验

`validateRooms()` 在应用启动时执行；发现错误直接抛出，避免玩家进入损坏关卡。

检查：

- 出生与出口范围；
- 检查点与收集物范围；
- 重复实体 ID；
- 哨兵射程、周期、速度和预警；
- 追逐幕墙速度和触发点；
- 段落标记与角色顺序；
- 出口支撑；
- 普通房间宽度和内容结构。

## 5. Debug 模式

URL 增加 `?debug=1`：

```text
https://.../index.html?debug=1
```

页面暴露 `window.__lostMemoryParkDebug`：

- `snapshot()`：获取当前状态、设备数量、锁、Boss、摄影机和性能计时。
- `startRoom(index)`：直接进入房间。
- `teleport(x,y)`：传送玩家。
- `echo(x,y)`：为残影管理回归测试放置一具死亡残影。
- `bossPhase(phase)` / `bossWaves(waves)`：设置 Boss 测试状态。
- `win()`：完成当前房间。
- `setCollections(shards,notes)`：设置收集数量。
- `choose(side)`：测试终章选择。
- `overlay(visible)`：开关碰撞调试层。
- `down(action)` / `up(action)`：自动化输入，支持 left/right/jump/drop/restart。
- `save()`：读取完整存档。

Debug Overlay 显示玩家/尖刺/触发区碰撞框、位置、摄影机和房间 ID。

- 遍历 30 个场景；
- 确认 24 个 3440 宽普通房间；

- 测试 Boss 未达波数拒绝、达标后推进；
- 测试持续向右在所有普通房间都会死亡；

## 7. 性能目标

### 帧预算

- 60 FPS：16.67ms/帧。
- 更新逻辑目标：< 3ms。
- Canvas 提交目标：< 6ms。
- UI 与其他：< 2ms。
- 保留至少 5ms 余量给浏览器合成和设备差异。

### 当前测量

压力房间：最终章普通房间 `choice-machine`，包含追逐、压榨机、聚光灯、两座哨兵、动作锁和大量平台。

在 1920×1080 自动化 Chrome 环境中，三次 5 秒样本：

- TaskDuration：约 0.34–0.37 秒/5 秒窗口；
- 平均 Canvas 绘制提交：约 0.51–0.55ms/帧；
- 平均更新：约 0.13–0.16ms/固定步；
- 渲染比例：1.5；
- 约 329–331 次绘制/更新样本。

说明：这是浏览器主线程/脚本侧测量，不等同于所有设备的 GPU 帧时间；真实发布仍需在目标设备人工试玩。

## 8. 性能优化清单

### 已实施

- 固定 60Hz，而非 120Hz 重复模拟。
- `desynchronized: true` 2D context 降低显示延迟。
- `alpha:false` 减少主画布合成成本。
- 背景、世界布景、前景三层缓存。
- 缓存按 1.25–1.5 高清比例生成，避免模糊。
- 手机紧凑触控视口使用 1.0 渲染比例，即 1280×720 backing canvas；常见手机 CSS 视口仍为超采样显示。
- 世界对象 X 轴视野裁剪。
- 粒子最多 70 个，默认强度 0.35。
- 投射物离开世界后原地压缩数组，不创建新数组。
- HUD 最多 15Hz 且只写变化值。
- 暂停/标题画面 10Hz 绘制。
- 减少动态全屏透明叠层。

### 继续监控

- 大量 Canvas `shadowBlur` 在低端 GPU 的成本。
- 3440×720 × 1.5 世界缓存内存。
- Boss 同屏弹幕峰值。
- 长时间游玩后的手机浏览器热降频。
- 最佳残影 localStorage 体积。

## 9. 画质回归标准

- 桌面 Debug snapshot 的 `render.dpr` 不低于 1.25。
- 触控手机紧凑视口 `render.dpr` 为 1.0，对应完整 1280×720 backing canvas，不允许再向下缩小。
- 1920×1080 窗口应为 1.5。
- stage/scenery/foreground cache key 必须包含 dpr。
- 缓存 canvas 的 backing size 必须乘 dpr。
- 不得重新使用 0.85 或 CSS 放大低清 backing canvas。
- 平台和尖刺在正式模式保留渐变与阴影。
