# 06 · 数据、存档、UI 与输入

## 1. 数据驱动原则

关卡内容使用接口描述，运行时在加载房间时创建可变副本。设计目标：新增房间或机关主要通过配置完成，而不是修改主循环分支。

## 2. 关键数据结构

### `Rect`

所有碰撞区域的基础：`x, y, w, h`。

### `RoomDef`

包含：

- 房间 ID、章节、名称、提示、背景；
- 出生、出口、世界尺寸；
- 平台、尖刺、陷阱、按钮、激光；
- 检查点、核心记忆、员工档案；
- 风区、大炮、压榨机、聚光灯；
- 段落标记、课程信息、地标、追逐幕墙、哨兵；
- Boss、攻击主题、合同、混合机制描述与可选 `TutorialSignDef` 场景指示牌。

### `BlockDef`

基础矩形 + `kind`，并按类型使用移动目标、速度、颜色、力、相位周期、组、崩塌时间或轨道参数。

### `SpikeDef`

方向、隐藏状态，以及可选线性移动或轨道移动。

### `SentryDef`

位置、射程、周期、弹速、预警、连发数、模式、标签与颜色。

### `ContractDefinition`

合同 ID、名称、说明、规则与可选目标值。

### `AccessibilitySettings`

音频、视觉、HUD、文字、游戏速度、预警、输入设备、触屏布局、颜色模式、残影和按键绑定。

## 3. 运行时状态

加载房间时：

- `BlockDef` → `BlockRun`：增加 baseX/baseY、active、lastX/lastY、crumbleTouched。
- `SpikeDef` → `SpikeRun`：增加 baseX/baseY、active、速度和 reveal。
- `ButtonDef` → `ButtonRun`：增加 pressed。

这样源数据保持不可变，死亡/重开只需重新创建运行时副本。

## 4. 存档结构 `V2Save`

主要字段：

| 字段 | 用途 |
|---|---|
| `version` | 当前结构版本 5 |
| `room` | 当前房间索引 |
| `respawnRoom/X/Y` | 最近检查点 |
| `shards` | 核心记忆 ID |
| `notes` | 员工档案 ID |
| `deaths/elapsed` | 总死亡与时间 |
| `achievements/endings` | 已解锁记录 |
| `unlockedRoom` | 章节选择上限 |
| `bestRooms` | 房间最佳时间、死亡、评级、辅助状态与额外挑战；旧存档中的热度/连拍字段只兼容读取，不再写入或显示 |
| `roomDeaths` | 各房间死亡数 |
| `bossStages` | Boss 已完成阶段 |
| `mode` | 当前模式 |
| `modeBests` | 模式最佳时间 |
| `ghostRooms` | 压缩后的最佳路线残影 |
| `runSeed` | 导演模式确定性种子 |
| `exploredRooms` | 房间最大探索比例 |
| `settings` | 当前设置 |

## 5. 三槽存档

localStorage 键：`lost-memory-park-remaster-slots-v1`。

数组固定三个元素，每个槽位独立保存：

- 进度、收集、结局；
- 最佳成绩和残影；
- 设置与按键；
- 当前模式。

删除槽位前使用浏览器确认框。

## 6. 旧存档迁移

`normalize()`：

1. 以 `newV2Save()` 创建完整默认结构。
2. 合并旧字段。
3. 深合并 settings 与 bindings。
4. 删除已废弃的 `skipBossStage`、`bonusRewind`、`extraDash`、dash/rewind/anchor 按键。
5. 补齐记录对象和数组。
6. 强制存档版本为 5。

读取顺序兼容 remaster、director、super 和旧 v2 键。

## 7. 保存时机

- 房间加载；
- 检查点；
- 收集核心记忆/档案；
- 死亡；
- 动作锁/Boss 阶段；
- 房间完成；
- 设置变更；
- 结局和模式完成。

`IWannaGame.persist()` 只发送克隆存档；真正写 localStorage 由 `main.ts` 完成。

## 8. 导入与导出

### 导出

将三槽数组序列化为格式化 JSON，浏览器下载 `失忆乐园-存档.json`。

### 导入

读取用户选择的 JSON，逐槽执行 `normalize()` 后写入 localStorage。解析失败显示“存档文件无效”。

## 9. UI 页面

### 标题页

主界面只显示新游戏、继续、更多内容、设置四个等宽入口。槽位、章节、计时、额外模式、档案和制作信息位于“更多内容”二级页。

### HUD

- 房间编号与本关进度；
- 本关阶段编号与当前“学习/练习/考验/终点”目标；
- 剩余跳跃；
- 残影、核心记忆、死亡、计时；
- 导演规则/Boss 攻势；
- 动作锁；
- 额外挑战与完成数量。

### 暂停页

继续、重新开始、设置、回标题，并显示当前目标。

### 档案页

核心记忆、员工档案、成就、房间最佳与残影记录。

### 结局页

结局名称、文本、核心记忆数、档案数、总时间。

## 10. HUD 性能策略

- 最多 15Hz 发送 HUD 数据。
- `setText()` 只有文本变化时写 `textContent`。
- `setWidth()` 只有宽度变化时写 style。
- 使用 `dataset` 状态避免每帧重建 DOM。
- Canvas 与 DOM 分层，游戏画面不重排页面布局。

## 11. 输入抽象

### 统一动作

运行时只接收 `left/right/jump/drop/restart`，暂停由应用层处理。

### 键盘

- 自定义绑定保存在 settings。
- 方向键始终作为备用。
- `A/D` 始终可左右移动，`W` 始终可跳跃，`S` 始终可下穿薄板。
- Space、Arrow 等会阻止页面滚动。
- keydown 与 keyup 分开处理，跳跃只在按下边沿写入缓冲。
- 活跃游戏中的鼠标右键会将屏幕坐标转换为世界坐标，仅删除命中的最新一具残影。

### 手柄

每帧轮询第一个 Gamepad：

- 左摇杆或十字键；
- A/0 键跳跃；
- 十字键下或摇杆向下穿过薄板；
- Start/9 暂停。

只有状态边沿变化时调用动作，避免每帧重复 keydown。

### 触屏

触屏默认使用 `auto`：检测到粗指针或 `maxTouchPoints > 0` 时，在实际游戏中显示左右、下穿、跳跃和暂停按钮；标题、设置、暂停、记忆弹窗和结局界面自动隐藏。也可设为始终显示或始终关闭。

- 使用 Pointer Events 与 pointer capture，支持多根手指独立持有动作；
- 左右方向区支持按住后跨过中线滑动换向；
- 同一动作使用引用计数，避免两根手指触发后其中一根松开导致另一根失效；
- `pointerup`、`pointercancel`、`lostpointercapture`、页面失焦和切后台都会释放动作，防止卡键；
- 可调整方向按钮大小、跳跃按钮大小、透明度、底部距离和左右手布局；
- 使用 `env(safe-area-inset-*)` 避开刘海、圆角和系统手势区；
- 竖屏显示旋转提示，横屏压缩标题页、设置页、HUD 与房间卡片；
- 可选短震动反馈；游戏运行时关闭画布默认触摸滚动。

## 12. 镜像模式输入

镜像模式把物理左右映射反转，同时 Canvas 使用 `scaleX(-1)`。输入层先把玩家物理意图转换为世界方向，保证内部碰撞仍使用标准坐标。

## 13. 焦点与可见性

- `blur`：暂停音频并打开暂停界面。
- `visibilitychange hidden`：同样暂停。
- `focus`：只有暂停、设置、结局均未打开时恢复音频。
- 避免多个本地 HTML 页面同时播放声音。

## 14. 设置默认值

- 主音量 0.8；音乐 0.7；音效 0.8；环境 0.45。
- 震动 0.2；闪光 0.65；粒子 0.35。
- 动态背景开启；高对比/粗轮廓关闭。
- HUD 完整；文字 1.0；游戏速度 1.0。
- 手柄开启；触屏为手机自动显示；触觉开启。
- 方向按钮 1.0 倍；跳跃按钮 1.12 倍；透明度 0.72；离底部 18px；右手跳跃布局。
- 最佳残影默认关闭。

## 15. 数据与 UI 验收

- 三槽互不覆盖。
- 页面刷新后检查点、收集和设置恢复。
- 旧存档不包含已移除动作字段。
- 导出后重新导入得到相同核心进度。
- HUD 隐藏模式不影响碰撞。
- 修改按键后立即生效并保存。
- 手机多点移动/跳跃、滑动换向、左右手布局与竖屏提示均通过浏览器自动化验收。
- 手机下穿键会在单向恢复平台上触发同一套 `drop` 动作。
- 复活安全区内残影自动删除，路线上的残影保留；右键只删除命中目标。
- 页面隐藏后无声音与模拟推进。
