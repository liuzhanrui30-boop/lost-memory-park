# 08 · 从零到一开发教程

本章说明如何从空目录逐步制作一个与《失忆乐园》架构相同的原创 Canvas 高难平台游戏。顺序强调“先可玩、后内容、再美术与发布”。

## 阶段 0：定义产品边界

先写一页设计约束：

- 玩家能做什么？这里只保留移动、双跳、重开。
- 玩家不能做什么？不攻击、不冲刺、不回溯。
- 一局多长？首次 30–45 分钟。
- 目标平台？桌面浏览器 16:9。
- 哪些内容不是第一版？多人、服务器、编辑器、付费。

如果边界不明确，后续每个系统都会膨胀。

## 阶段 1：建立工程

```bash
mkdir lost-memory-park
cd lost-memory-park
npm init -y
npm install -D vite typescript vitest
```

创建：

- `index.html`；
- `src/main.ts`；
- `src/style.css`；
- `tsconfig.json`；
- `vite.config.ts`；
- `vitest.config.ts`。

先让页面显示一个 1280×720 Canvas，不写关卡。

## 阶段 2：实现最小角色

只实现：

1. `x/y/vx/vy`；
2. 左右输入；
3. 重力；
4. 地面矩形碰撞；
5. 跳跃；
6. requestAnimationFrame 绘制。

此时只画矩形角色和一块地面。不要先做菜单、剧情或 30 个关卡。

## 阶段 3：固定步长

把显示循环与物理更新分开：

```ts
const STEP=1/60;
accumulator+=delta;
while(accumulator>=STEP){
  update(STEP);
  accumulator-=STEP;
}
draw();
```

随后在 60Hz 与 144Hz 屏幕验证跳跃高度一致。

## 阶段 4：打磨运动学

按顺序加入：

- 目标速度与加速度；
- 地面急停；
- 空中修正；
- 跳跃缓冲；
- 土狼时间；
- 松键短跳；
- 二段跳；
- 顶点低重力与下落高重力。

每加入一项就写纯函数测试或重复操作测试。手感确认前不要大量制作关卡。

## 阶段 5：可靠碰撞

1. 将每帧位移拆为最多 3 像素的小段。
2. X/Y 分轴处理。
3. 加入单向平台。
4. 加入脚下支撑探针。
5. 加入头顶边角修正。
6. 加入移动平台 `lastX/lastY` 和动量继承。

建立专门测试房：高速横移、窄平台、低天花板、移动台、墙角。

## 阶段 6：数据驱动房间

定义 `Rect`、`BlockDef`、`SpikeDef`、`RoomDef`。把第一关写成对象，不在代码里硬编码坐标。

加载时将定义复制为运行时对象：

```ts
runtimeBlocks=room.blocks.map(block=>({
  ...block,
  baseX:block.x,
  baseY:block.y,
  active:true,
  lastX:block.x,
  lastY:block.y,
}));
```

实现 `validateRooms()`，在启动时阻止非法数据。

## 阶段 7：陷阱系统

从最简单开始：

- 显示隐藏尖刺；
- 假平台掉落；
- 平台横移；
- 弹板发射。

每个陷阱都使用 trigger 区和 target ID。房间重开时清空 triggered 集合并恢复对象。

## 阶段 8：检查点与死亡

- 伤害统一调用 `die(reason)`。
- 死亡只记录状态，不立刻重建整个应用。
- 0.2 秒后 `respawn()`。
- 最近检查点保存房间和坐标。
- 重生重置房间临时对象。

此时快速重开必须足够快，才能支持高难玩法。

## 阶段 9：摄影机

先实现简单跟随，再改为宽死区：

- 角色在屏幕 40%–56% 之间时镜头不动。
- 超界时只追到边界。
- 背景固定，不做视差。
- 震动只应用到世界层，不改变 UI。

摄影机舒适度应在复杂关卡前确定。

## 阶段 10：机关词汇

按一章只加入少量机制：

- 第 1 批：移动台、尖刺、激光、按钮；
- 第 2 批：冰、黏性、弹床、崩塌；
- 第 3 批：相位、轨道、风、输送带；
- 第 4 批：压榨机、聚光灯、远程哨兵、追逐。

每个周期机制先写纯函数 `stateAt(time)`，再接入主循环和绘制。

## 阶段 11：四幕关卡

先制作一个 3440 宽“黄金房间”：

1. 第一幕教机制；
2. 第二幕组合；
3. 第三幕动作锁；
4. 第四幕返场与高风险支路。

黄金房间通过试玩后，再复制结构而不是复制坐标。为 24 个房间编写不同机制配方和标签。

## 阶段 12：远程攻击

建立统一弹丸结构：位置、速度、半径、预警、寿命、重力、模式。

先做点射，再通过旋转/缩放基础速度生成抛射、扇射、镜射、连射。限制每章攻击词汇，避免所有关卡看起来一样乱。

## 阶段 13：Boss

Boss 不需要复杂 AI，可以使用阶段状态机：

```text
攻击波 → 波数达标 → 机关可用 → 下一阶段
```

攻击序列确定性生成。先验证按钮不能提前推进，再制作造型和剧情。

## 阶段 14：进度与存档

- 定义版本化 `SaveData`。
- 使用 `newSave()` 生成所有默认字段。
- `normalize()` 合并旧存档并删除废弃字段。
- localStorage 保存三槽数组。
- 收集、检查点、死亡、设置和完成时写入。
- 增加 JSON 导入导出，防止本地数据丢失。

## 阶段 15：UI 与输入设备

先完成键盘，再加入：

- HUD 差量更新；
- 暂停；
- 设置与改键；
- 手柄轮询；
- 触屏 pointer 事件；
- 失焦和隐藏页面暂停。

UI 不应直接写玩家位置或机关状态。

## 阶段 16：叙事与结局

- 把核心剧情拆成 12 个短收集文本。
- 环境招牌承担氛围与提示。
- 结局只依赖明确存档条件。
- 先实现三个主结局，再加入全收集隐藏选择。

## 阶段 17：美术替换

从矩形原型升级为纸雕/黏土 Canvas：

1. 建立章节色板。
2. 平台加入暗面、表面和描边。
3. 尖刺加入折面和统一危险色。
4. 角色加入头身、表情、挤压拉伸。
5. 背景加入纸纹和固定远景。
6. 每章制作三个大型地标。

不要在碰撞未稳定前投入大量美术。

## 阶段 18：音频

使用 WebAudio 或原创文件：

- 首次点击解锁；
- 总线分离；
- 跳跃、落地、死亡、预警优先；
- 音乐随章节和热度变化；
- 失焦必须静音。

## 阶段 19：高清与性能

1. 建立可重复压力房。
2. 先测量更新和绘制。
3. 缓存完全静态层。
4. 裁剪视野外对象。
5. 限制粒子和投射物。
6. HUD 降频。
7. 使用 1.25–1.5 backing scale；所有缓存必须同分辨率。
8. 1920×1080 连续测量三次，确认远低于 16.67ms。

不要用 0.85 低分辨率掩盖绘制问题。

## 阶段 20：测试与发布

- 单元测试纯函数和数据。
- 浏览器自动遍历房间。
- 验证持续向右必死。
- 验证 Boss 阶段门槛。
- 构建单文件。
- 部署 GitHub Pages。
- 发布后从公开 URL 再验收一次。

## 推荐里程碑

| 里程碑 | 可交付结果 |
|---|---|
| M1 | 单房间矩形跑跳原型 |
| M2 | 手感和碰撞稳定 |
| M3 | 一关四幕垂直切片 |
| M4 | 第一章 + Boss + 存档 |
| M5 | 四章完整主线 |
| M6 | 美术、音频、结局与模式 |
| M7 | 高清性能、测试、单文件与上线 |

每个里程碑都应是可运行版本，不要等全部系统完成后第一次整合。
