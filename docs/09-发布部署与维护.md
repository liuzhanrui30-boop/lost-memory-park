# 09 · 发布、部署与维护

## 1. 发布物类型

### GitHub Pages

仓库根目录 `index.html` 是正式公开版本。当前地址：

<https://liuzhanrui30-boop.github.io/lost-memory-park/>

### 离线单文件

`source/dist/lost-memory-park.html` 包含全部 CSS 和 JavaScript，可直接发送给朋友。

### 标准 Vite 构建

`source/dist/index.html` + `source/dist/assets/`，适合常规静态托管。

## 2. 环境要求

- Node.js 22+；
- npm；
- Git；
- 可选 GitHub CLI；
- 可选 itch.io butler。

## 3. 本地验证

```bash
cd source
npm ci
npm test
npm run build
```

必须确认：

- TypeScript 无错误；
- 98 项测试通过；
- `dist/lost-memory-park.html` 存在；
- 双击单文件能启动；
- 音频只在用户点击进入后开始。

## 4. 单文件生成原理

Vite 先生成：

```text
dist/index.html
dist/assets/index-xxxx.js
dist/assets/index-xxxx.css
```

`make-standalone.mjs`：

1. 读取 `dist/index.html`；
2. 找到 module script 和 stylesheet；
3. 读取 JS/CSS 内容；
4. 转义 `</script` / `</style`；
5. 替换外链标签为内嵌标签；
6. 输出 `dist/lost-memory-park.html`。

因为游戏无图片/音频外链，单文件即可完整运行。

## 5. 同步 GitHub Pages

```bash
cd source
npm run release:pages
```

该命令依次运行测试、TypeScript 检查、生产构建、单文件生成，将 `dist/lost-memory-park.html` 复制到仓库根目录 `index.html`，最后比较两者 SHA-256，防止源码和发布页面漂移。

随后：

```bash
git add index.html source docs README.md CHANGELOG.md
git commit -m "Release v12.6"
git push
```

推送 `main` 后由 `.github/workflows/deploy-pages.yml` 再次测试并自动部署 GitHub Pages。

## 6. CI 验证

`.github/workflows/verify.yml` 用于 Pull Request 和手动验证：

1. 检出仓库；
2. 配置 Node 22；
3. `npm ci`；
4. `npm test`；
5. `npm run build`；
6. `npm run check:release`；
7. 上传可下载的单文件构建产物。

`.github/workflows/deploy-pages.yml` 在个人仓库 `main` 更新时执行相同质量门，并通过官方 Pages artifact 自动部署。测试失败时不会覆盖线上稳定版本。

## 7. GitHub Pages 首次设置

若复制仓库：

1. GitHub 仓库 Settings；
2. Pages；
3. Source 选择 **GitHub Actions**；
4. 在 Actions 页面手动运行 `Test, build and deploy Pages`；
5. 等待 `github-pages` 环境部署完成。

也可通过 API 创建 Pages 配置，但必须明确使用个人仓库，不能误操作组织仓库。

## 8. itch.io 发布

使用标准 Vite 文件或包含 `index.html` 的 ZIP：

```text
itch-package/
└── index.html
```

上传时选择：

- Kind of project：HTML；
- This file will be played in the browser；
- 自动启动全屏/最大尺寸；
- 尺寸保持 16:9。

如果使用 butler：

```bash
butler push package 用户名/项目名:html --userversion 12.6.0
```

## 9. 版本规则

采用语义化版本：

- Major：关卡/架构大改，可能影响存档或规则。
- Minor：新内容、显著美术/性能升级。
- Patch：Bug 修复、数值微调、文档修正。

每次发布同步修改：

- `source/package.json`；
- `source/package-lock.json`；
- 标题页版本文字；
- 制作信息；
- `CHANGELOG.md`；
- itch.io userversion（如使用）。

## 10. 存档兼容

如果新增字段：

1. 更新接口；
2. 更新 `newV2Save()` 默认值；
3. 在 `normalize()` 深合并；
4. 添加旧存档迁移测试；
5. 只有破坏性结构变化才提升 `version`。

不要直接假设 localStorage 中一定是最新结构。

## 12. 回滚

若线上版本出现严重问题：

1. 在 Git 中找到上一个稳定提交；
2. 使用 `git revert` 回退引入问题的提交；
3. 推送 `main`，Actions 会从回退后的完整源码重新构建线上版本；
4. 在新分支修复 source；
5. 测试完成后重新执行发布流程。

不要删除仓库或 Pages 配置来回滚。

## 13. 长期维护

- 每次新增机制同步文档与测试。
- 每个版本至少保留一张标准分辨率截图。
- 监控单文件体积和 localStorage 大小。
- 避免引入运行时 CDN 依赖，保持离线能力。
- 组织/团队权限必须明确；本项目部署只操作个人仓库 `liuzhanrui30-boop/lost-memory-park`。
